# iOS Port Handoff

This document covers everything needed to build and run Molepipe on iOS. The
iOS port follows the same architecture as Android: Go gomobile wraps the backend
into a framework, Rust torhost provides the Arti onion service, and a native
shell loads the shared web UI.

## macOS-Only Build Checklist

Everything below requires macOS with Xcode. Cannot be run from Linux.

### Prerequisites (one-time)

```bash
# Rust iOS targets
rustup target add aarch64-apple-ios aarch64-apple-ios-sim

# gomobile
go install golang.org/x/mobile/cmd/gomobile@latest
go install golang.org/x/mobile/cmd/gobind@latest
gomobile init

# xcodegen
brew install xcodegen
```

### Build Steps

```bash
cd ios

# Step 1: Cross-compile Rust torhost for iOS
# Produces: ../backend/internal/tor/artihost/lib/ios-arm64/libtorhost.a
#           ../backend/internal/tor/artihost/lib/iossim-arm64/libtorhost.a
bash build-torhost.sh

# Step 2: gomobile bind → XCFramework
# Produces: Molepipe.xcframework
bash build-xcframework.sh

# Step 3: Generate Xcode project
# Produces: Molepipe.xcodeproj/
xcodegen generate

# Step 4a: Build for simulator (CLI)
bash build-app.sh --simulator

# Step 4b: Build for device
# Open Molepipe.xcodeproj in Xcode, set signing team, run from Xcode.
```

## Architecture Parity Notes

| Concept | Android | iOS |
|---|---|---|
| Backend wrapper | `Backend.kt` (singleton object) | `Backend.swift` (final class, `@Published`) |
| Service lifecycle | `BackendService` (foreground service) | `BackendService.swift` (background tasks) |
| WebView bridge | `@JavascriptInterface` inner class | `WKScriptMessageHandler` + JS injection |
| Save image | `MediaStore` + `ContentValues` | `PHPhotoLibrary.shared().performChanges()` |
| Share image | `Intent.ACTION_SEND` + `FileProvider` | `UIActivityViewController` |
| Open URL | `Intent.ACTION_VIEW` | `UIApplication.shared.open()` |
| Dynamic color | Material You `system_accent1_*` | Stub `""` (no equivalent) |
| Status bars | `WindowInsetsControllerCompat` | `UIStatusBarStyle` / `overrideUserInterfaceStyle` |
| Background | Foreground service + `PARTIAL_WAKE_LOCK` | `beginBackgroundTask` + `BGTaskScheduler` |
| Notifications | `NotificationManager` + channels | `UNUserNotificationCenter` |
| Tor dormant | `setDormant()` → `DormantMode::Soft` | Same Go call via gomobile |
| Back button | `handleAndroidBack` JS callback | `WKWebView.canGoBack()` |
| Kill = stop | `onDestroy` → `Backend.stop()` | `willTerminate` → `Backend.stop()` |

## Regenerating the XCFramework

When Go core code changes (new/modified exported functions in `mobile/`):

```bash
cd ios && bash build-xcframework.sh
```

The Rust static libraries do NOT need to be rebuilt unless `torhost/` changes.

## Regenerating the Xcode Project

When adding/removing Swift files or changing build settings:

```bash
cd ios && xcodegen generate
```

The project.yml is the source of truth; the .xcodeproj is gitignored.

## Troubleshooting

### `cargo build` fails with "target not found"
Run: `rustup target add aarch64-apple-ios aarch64-apple-ios-sim`

### `gomobile bind` fails with "unable to find import"
Ensure the Rust static libraries exist in `backend/internal/tor/artihost/lib/ios-arm64/`
and `lib/iossim-arm64/`. Run `build-torhost.sh` first.

### `xcodegen generate` fails
Ensure xcodegen is installed: `brew install xcodegen`. Check `project.yml` for
YAML syntax errors.

### Xcode build fails with "no such module 'Mobile'"
The XCFramework was not built or not found. Run `build-xcframework.sh` first.

### WebView shows blank page
The backend URL may have expired. The app should automatically reload when
the backend state changes. Check console logs for backend start errors.

## Crypto Constants (DO NOT CHANGE)

These constants are part of the wire protocol and must not be modified:
- `"onion-chat/v1"`, `"onion-chat/v2"` — protocol identifiers
- `"onionchat-update-manifest-v1"` — update manifest signing
- `"onionchat-pair:"` — pairing prefix

## Platform Parity Extras (iOS-Only)

The iOS port adds these extras not present in Android:

1. **Full Tor from start** — Arti is always active, no "Tor-disabled" mode
2. **Full parity + extras** — All Android features plus iOS-specific polish
3. **Keychain storage** — `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`
   for sensitive data (future: private keys, session tokens)
4. **Apple-native share/save** — `UIActivityViewController` and
   `PHPhotoLibrary` instead of Android's Intent/MediaStore
